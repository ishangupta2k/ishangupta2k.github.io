Purchase Order Automation for Convenience Stores

Business Intelligence & Automation · June 5, 2026
Automationn8nNode.jsMicrosoft ExcelJavaScript

A scheduled n8n and Node.js pipeline that turns each store's daily POS reports into vendor-ready purchase orders across 2 locations, ~20 vendors, and 5,000+ SKUs — replacing 6 hours/day of manual spreadsheet work.

Try the interactive demo ↗

A sanitized, in-browser version of this system that anyone can run with sample data, no install. (The production pipeline itself runs privately for the business.)

My involvement: Business workflow owner, automation planner, rule designer, tester, and reviewer.

The opportunity

Vendor ordering for the stores depended on sales reports, inventory exports, vendor lists, item masters, case quantities, linked scan codes, and manual spreadsheet review. The work was repetitive, but it still required business judgment because suggested quantities had to match how ordering actually works in the store.

The challenges

  • Sales, inventory, item, vendor, and linked scan-code data lived in separate files.
  • Manual order building was slow and easy to miscalculate.
  • Case quantities, linked scan codes, and pack/single relationships created edge cases.
  • Orders still needed a human review step before being used.
  • The same ordering logic had to run for each store without maintaining a separate system per location.

How the n8n workflow works

Two n8n workflows run the pipeline every morning, one per store (Sunoco and United), both fed by the Modisoft POS. Each runs end to end through 22 nodes, with no manual step until the final review.

Schedule 6:15 AM  ->  pull Modisoft reports from Gmail  ->  parse the Excel files
  ->  sync inventory + sales into a master Excel workbook (Microsoft Graph)
  ->  download the recalculated workbook  ->  run the Node.js generator
  ->  vendor purchase orders ready for review
  1. Scheduled trigger. A Schedule Trigger fires daily at 6:15 AM, so orders are ready before the store's ordering window.
  2. Pull the day's reports from email. A Gmail node fetches that morning's Modisoft Inventory Report and Item Sales Report .xlsx attachments (filtered by sender, subject, and a one-day window). A Code node keeps only the latest of each, and an IF node routes the inventory and sales files down separate branches.
  3. Parse the spreadsheets. Extract-from-File nodes read each .xlsx, and Code nodes normalize the rows, cleaning text and preserving scan codes exactly (stripping stray .0 and keeping leading zeros so barcodes never break).
  4. Sync into the master workbook (Microsoft Graph + Excel). The workflow locates the store's master workbook in OneDrive and, through the Microsoft Graph API, clears and rewrites the InventoryData table with the day's snapshot, then appends new rows to a running SalesHistory table. A Code node converts Excel serial dates and drops duplicates, and an IF node skips the append when there is nothing new, so sales history accumulates cleanly without double-counting.
  5. Generate the purchase orders. After a short wait for Excel to recalculate, the workflow downloads the updated workbook, writes it to the self-hosted working folder, and runs the Node.js generator through an Execute Command node. The generator applies the ordering rules (daily sales rate, target units, inventory credit, needed units, suggested cases, final order, and linked pack/single rollups) and writes per-vendor and combined purchase order workbooks, CSV exports, and a run manifest.
  6. Human review. Nothing is ordered automatically. Each workbook includes a manual-adjustment column and the underlying calculation detail, so staff confirm quantities before placing the order.
Reliability built in: deduplicated, skip-when-empty sales-history appends; a recalculation wait so downloads are never stale; and the same workflow cloned per store, so a new store or vendor is a copy-and-configure, not a rebuild.

The result

  • Eliminated 6 hours/day of manual counting, cross-referencing, and order building across both stores.
  • Covers ~20 vendors and 5,000+ SKUs with vendor-specific purchase order generation.
  • Reduced ordering errors by producing reviewable, structured outputs instead of manual spreadsheet assembly.
  • Scaled across both store locations (Sunoco and United) by cloning and reconfiguring the workflow per store, not rebuilding.

Proof

  • Generated vendor purchase order — each vendor gets a workbook with suggested quantities, inventory credits, and a manual adjustment column for final review before placing the order.
  • Calculation detail sheet — shows the underlying math for each SKU including daily sales rate, target units, current inventory, and linked scan-code rollups (e.g., combining pack and single sales into one orderable item).

Tools used

  • Core stack: Node.js, JavaScript, ExcelJS
  • Integrations: Gmail API, Microsoft Graph (Excel Online tables), OneDrive
  • Data formats: XLSX, CSV
  • Infrastructure: Self-hosted n8n (Docker), GitHub, AI-assisted development
