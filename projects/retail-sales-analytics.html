Retail Sales Analytics

Business Intelligence & Automation · June 26, 2026
Data AnalysisSQLPythonSQLiteTableauAI

A retail sales + inventory analytics project over sanitized point-of-sale data: Python loads CSVs into SQLite, SQL surfaces revenue, stockout risk, and master-data gaps, a published Tableau dashboard visualizes performance, and a grounded AI assistant answers questions only from approved SQL-backed tools.

Live dashboard ↗ Source on GitHub ↗

My involvement: Sole builder — defined the business problem, modeled the data, wrote the SQL analysis and Python loaders, designed and published the Tableau dashboard, and built a grounded AI assistant with evaluation tests.

The business problem

A retail operator needs a lightweight way to review sales performance, inventory exceptions, stockout risk, and item master-data gaps from sanitized point-of-sale and inventory exports — without a heavy BI stack.

The data

  • data/sales.csv: daily item-level sales, 2026-05-18 to 2026-06-22 (19,098 rows, 35 distinct dates).
  • data/inventory.csv: one inventory snapshot from 2026-06-23 (14,444 rows).
  • Sanitized: revenue is useful for relative analysis, not audited reporting. scan_code is loaded as text so leading zeros are preserved.

The approach

  • Load both CSVs into SQLite with a standard-library Python loader (scripts/load_sqlite.py).
  • Use SQL to compute department revenue, top sellers, daily trends, low inventory, stockout risk, overstock candidates, over/short exceptions, and sold items missing from inventory.
  • Build a minimal assistant that routes natural-language questions to approved SQLite-backed tools and refuses unsupported questions instead of guessing.
  • Add evaluation tests covering grounded answers and refusal behavior.
  • Document source data, assumptions, assistant design, and limitations in docs/.

Sample findings

  • Highest-revenue departments: BEER & WINE, LOTTERY, GENERIC CIGARETTE.
  • Highest-revenue day: 2026-05-21 — 7,400.72 sanitized revenue, 2,533 units.
  • Stockout-risk query flags 1,298 items with low/negative on-hand that still have sales activity.
  • 32 sold scan codes are missing from the inventory snapshot, pointing to item-master / inventory-file gaps.
  • The uncategorized (Null) department is excluded from revenue ranking and flagged as a master-data gap.

Skills demonstrated

  • Python data loading with standard-library CSV and SQLite tooling.
  • SQL aggregation, joins, exception queries, and business-metric design.
  • Dashboard/report design for sales and inventory operations (Tableau Public).
  • Grounded AI assistant design using approved SQL-backed tools, with refusal behavior.

Limitations

  • No customer, receipt, basket, or loyalty data; no cost, margin, or profit fields.
  • Inventory is a single snapshot, not history. Revenue is sanitized/scaled.
  • Daily data can't explain causes like promotions, staffing, holidays, or weather.

Tools used

  • Data & analysis: Python (standard library), SQLite, SQL
  • Visualization: Tableau Public
  • AI: Grounded assistant over approved SQL-backed tools, with evaluation tests
  • Docs: Data dictionary, assistant design notes, summary report
